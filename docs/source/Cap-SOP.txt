
Capitaline BM Agent — SOP & Playbook
BM Factory · System 3 (Capitaline) · Agentic, browser-only Indian TP comparable search, evidence, gates and hand-off to TAIGA · v1.0 · 7 Nov 2026
1. Executive summary
This SOP is the operating manual the Capitaline BM agent follows end to end. A partner types one line from a phone or iPad — year, industry, product — and the agent on the System 3 desktop runs the full Capitaline search in Chrome, exports every dump, files it as BM Backup on SharePoint, and hands it to the TAIGA Document Enabler. From there the economic analysis starts in TAIGA. No database API and no extra licence spend are involved: the agent uses the firm's existing licensed desktop seat, at human pace, operating the Capitaline Windows application through computer use.
Element
Design decision
Trigger
One-line command from mobile / iPad (grammar in §4). Minimum: FY + industry + product. Everything else defaults.
Executor
Capitaline desktop application on the dedicated Windows System 3 desktop (Hyderabad), operated by Claude through computer use from the Claude desktop app; Claude in Chrome only for SharePoint and websites. No API. SBC's subscription is the desktop version, which does not run on Mac.
Search logic
Eight-layer Capitaline classification sweep (NIC code → NIC activity → industry → ITC/HS product code → product name → raw material → segment → business-activity text), all combinations, de-duplicated.
Screens
Quantitative waterfall then qualitative annual-report review, each reject carrying a reason code and evidence link.
Law
Section 92C read with Rules 10B, 10C, 10CA and 10D of the Income-tax Act 1961 / Rules 1962 (FY 2025-26 = AY 2026-27); Income-tax Act 2025 mapping flagged for tax year 2026-27 onward.
Storage
SharePoint client folder → 03 TAIGA & Workings → BM Backup → Capitaline → <RunID>, plus a firm-level BM Factory library for reusable industry searches.
Gates
G0–G8. Machine gates self-pass on evidence; three human gates — G2 strategy (new industry only), G5 reject list (manager), G7 final set (partner).
Self-learning
Every correction from a manager or partner becomes a rule in the Lessons Register, which the agent reads before each run (§10).
Hand-off
Manifest + files → TAIGA Document Enabler → TAIGA benchmarking study → PLI, range, Local File.

Licence gate (read first).  Capitaline does not publish its subscriber terms, and the ICAI-scheme Capitaline TP online licence is sold per member. Before go-live, obtain written confirmation from C-MOTS that agent-operated, human-paced browsing on SBC's licensed seat for SBC's own client engagements is permitted, and that storing client-specific search outputs in SBC's own SharePoint and TAIGA is within the licence. Do not let TAIGA re-sell or white-label Capitaline-sourced data to third-party firms without a redistribution licence. §11 covers the full position.

5. Legal framework the agent enforces
Provision
Requirement
How the SOP implements it
s.92C(1)–(2)
ALP by most appropriate method; where more than one price, range / arithmetic mean per rules.
PLI and method fixed at G0, locked at G2; range computed at G6.
Rule 10B(1)(e)
TNMM: net profit margin relative to costs, sales or assets of comparable uncontrolled transactions.
Operating PLI built from Capitaline P&L fields; non-operating items stripped (§7.6).
Rule 10B(2)–(3)
Comparability: specific characteristics, FAR, contractual terms, market conditions; reasonably accurate adjustments.
Qualitative screen (G5) tests FAR and business profile from annual reports; adjustments logged.
Rule 10B(4) and proviso
Data of the FY of the transaction; earlier two years admissible where they reveal facts with influence on pricing.
Year codes 202603 / 202503 / 202403 pulled; year-wise availability recorded per company.
Rule 10C
Most appropriate method considering nature of transaction, functions, data availability and reliability.
Method rationale cell in the command record; agent rejects mismatched PLI (e.g. GP for a service provider) at G0.
Rule 10CA(2)–(3)
Multiple-year data: weighted average of current and up to two preceding years; if current-year data unavailable at the 3CEB due date, the two preceding years.
Weighted-average PLI in Cap-Matrix; "refresh" mode re-runs when current-year data becomes available during assessment.
Rule 10CA(4)–(6)
Range 35th–65th percentile when dataset has six or more entries; percentile position rules; median when outside.
Exact percentile-position formulas in Cap-Matrix (not Excel PERCENTILE).
Rule 10CA(7) + s.92C(2) proviso
Fewer than six entries: arithmetic mean with tolerance (3%; 1% for wholesale traders as notified).
Mean + tolerance band computed automatically; tolerance % configurable.
Rule 10D(1)(g)–(m), 10D(3)
Record of comparables, comparability analysis, methods considered, workings, assumptions and adjustments, with supporting published data.
Evidence log, Show-sql captures, waterfall, accept/reject matrix, annual-report extracts stored per RunID (§8).
Income-tax Act 2025
Applies from tax year 2026-27; TP provisions carried into the new Act and Rules 2026.
Agent writes the 1961 references for FY 2025-26 and the 2025-Act section map (from the SBC APA alert library) for tax year 2026-27 runs.

Case law. Judicial guard-rails encoded as reject-rule checks (cite only after tp-caselaw-engine pinpoint verification):
Functional comparability over label — Rampgreen Solutions (P) Ltd v CIT (Delhi HC, 2015): KPO / BPO and functionally different entities are excluded; the agent never accepts on NIC code alone.
High profit alone is no ground to reject — Chryscapital Investment Advisors (India) (P) Ltd v DCIT (Delhi HC, 2015): super-normal margin triggers a check for abnormal circumstances, not automatic rejection.
Taxpayer may exclude its own wrongly-included comparables — Quark Systems (P) Ltd v DCIT (ITAT Chandigarh SB, 2009): the agent keeps prior-year sets under review rather than locked.
Consistent filters, no cherry-picking — the same quantitative thresholds apply to every company in a run; any one-off exclusion needs a reason code plus partner note.

7. Step-by-step procedure (agent run sheet)
7.1  G0 — Parse and plan
Read the Lessons Register and the industry library index first; reuse a confirmed strategy for the same NIC + product if it exists.
Resolve industry → NIC-2008 (section / division / group / class / sub-class), Capitaline industry name(s), sector; product → synonyms, ITC-HS 4/6/8-digit codes, raw-material terms.
Issue RunID = CAP-<FY>-<client-slug | LIB>-<YYYYMMDD>-<nn>. Write command.json. Post "Run started" in the chat (one line).
7.2  G1 — Environment and session
tabs_context → open a new Capitaline tab (never reuse the partner's tabs). Confirm the logged-in banner, subscription name and data date on the home screen; screenshot.
If logged out: use the saved Chrome profile credential only (the agent never types or stores a password from chat). OTP / CAPTCHA → message Revanth "System 3 login needs you" and pause the run with a resume code.
Check the watcher heartbeat file in BM Factory/_status; if stale, alert IT and switch to the manual-capture fallback (§9, F7).
7.3  G2 — Build the eight-layer strategy (Screener)

Query pattern

Exact class(es) e.g. 6201, 6202; then parent group 620 as widening pass

For each layer: Screener → Domain = All companies (standalone) → move to the right box → Filter → table → field → criteria (use Show Criteria Values to pick valid values, never free-type a code) → Year Selection = year-end ≥ 202403 and ≤ 202603 → Parse → Show sql (copy SQL into strategy.json) → Run Query.
Combinations: L1∪L2∪L3 as the classification universe; L4∪L5∪L6 as the product universe; L7 and L8 as catch-nets. Each layer is also run alone so counts are attributable.
G2 auto-passes when the NIC + product key already exists in the industry library with a manager-approved strategy; otherwise post the strategy card for APPROVE.
7.4  G3 — Extract the universe
On each output screen: Save (CSV) and Export → MS-Excel; filenames are set by the watcher to <RunID>_L<n>_<field>_<seq>.<ext>.
If export is disabled or blocked: read the result grid with read_page, write it into the evidence log as a table, and capture screenshots (fallback F3).
Build the union on Capitaline company code (fallback: normalised name + CIN). Reconcile: Σ layer counts ≥ union count; union count = distinct codes. Any layer with 0 rows → widen once (parent NIC / synonym) and log why.
Size guard: union > 1,500 → add the NIC-class intersection; < 15 → add widening passes before moving on.
Create a Peer Set named <RunID>-UNIVERSE from the union (lets the financial pull run in one Screener domain).

7.7  G6 — PLI and arm's length range
Cap-Matrix.xlsx computes year-wise and weighted-average PLI (Σ numerator ÷ Σ denominator across available years, Rule 10CA(2)).
n ≥ 6: 35th / median / 65th by Rule 10CA position rule (position = n × p; integer → mean of that and next value; otherwise next higher). n < 6: arithmetic mean ± tolerance.
Tested-party PLI entered or pulled from TAIGA; status = within / below / above range, with the adjustment that would follow.
7.8  G7 — Package, file and hand off
Generate annexures: A — search process (layers, SQL, counts, waterfall); B — accept/reject matrix; C — financials of accepted comparables; D — business descriptions. Word + Excel.
Watcher writes _manifest.json (file, layer, sha256, size, time, SharePoint URL). Agent verifies every file listed in the evidence log is in the manifest.
Write the Document Enabler job (jobs/<RunID>.json) naming the TAIGA engagement, study name "Capitaline · <industry> · FY25-26", PLI and file list. Partner APPROVE G7 before TAIGA Local File generation.
7.9  G8 — Close
One digest to the partner (RunID, counts funnel, range, approvals pending, links). No other mail.
Run record + metrics (duration, retries, fallbacks used, human touches) to 99-Logs; lessons delta to the Lessons Register; industry library updated when G5 and G7 approvals exist.

10. Self-learning harness
Capture — every REWORK, approval comment, Teams / mail instruction tagged to a RunID becomes a candidate lesson: trigger · rule · scope (all runs / industry / client) · source quote · date · approver.
Promote — a lesson applies automatically once the partner or the manager who gave it confirms; contradictory lessons are held for the partner.
Apply — the agent reads the Lessons Register at G0 and states which lessons it applied in the run record.
Measure — per run: human touches, REWORK count, fallbacks used, time per gate. The SBC Agent Harness evolution agent reviews weekly and proposes SOP / skill edits.
Version — the SOP and the capitaline-tp-search skill carry a version number; every edit cites the lesson that caused it.

12. Strategic lens — better ways and leverage points
Lens
Insight → action
Hidden assumption
That the agent must re-run the full universe every time. Leverage: the industry library — 60–70% of SBC runs fall in ~25 NIC families; reuse approved strategies and refresh only the year.
Opposing view
A TPO may argue an automated search is unreliable. Counter: the evidence chain is stronger than a manual search (SQL, timestamps, hashes, reason codes).
Role lens — manager
The manager's time moves from clicking to judging: only G2 (new industries) and G5.
Role lens — IT
One always-on desktop per database. That is the whole infrastructure bill.
Contrarian takeaway
The real moat is not the search. It is the Lessons Register and the reason-coded accept/reject history, which compound with every run.
Reusable model
The same gate model (G0–G8), folder taxonomy and command grammar apply unchanged to Prowess (System 2), ACE TP (System 4) and TP Catalyst (System 1); only §7.3 changes per database.
Leverage point
Cross-database union in TAIGA (Capitaline + Prowess + ACE) on CIN — gives the widest defensible set and catches database-specific misclassification.
